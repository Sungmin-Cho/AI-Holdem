## Common boundaries

The app service and `tools/game-loop.js` retain lifecycle ownership. LLM opponents remain tool-free runtime children. Existing raw decisions, forced actions, policy versions, assistance evidence, training authority, and review history are never relabeled retrospectively. An unknown ownership, termination, provenance, or recovery state cannot become success. New settings cross the supported lobby and legacy CLI paths, durable setup/config, and resume. Tests demonstrate delivery contracts; they do not establish poker strength, GTO correctness, learning effect, sufficient model thinking time, or Windows latency improvement without corresponding measurements.

## #173 — Child termination diagnostics and close races

Current path: `tools/player-runtime.js:start` registers handles → `runOnce` timeout or `dispose` invokes `killAndConfirmClose` → `tools/game-loop.js:requestStop` persists `cleanupError` in `loop-state.json` → resume/rollback readers refuse unsafe cleanup. The runtime tracks `closed` through `done` fulfillment; rejection is deliberately not close evidence. `kill(false)` is currently an immediate failure, and cleanup persistence does not write `loop.log`.

Enrich the registry entry and errors with a bounded, explicit diagnostic projection: runtime kind, purpose, model, pid, signal, elapsed wait, configured wait, close observation, and failure reason. Do not log prompts, raw output, session secrets, or inherited environment. Log `cleanup-failed` even if no loop-state file exists; state persistence and logging are independently best effort and cannot hide the original failure. Preserve machine-readable error codes and exit semantics.

Separate child `close` evidence from command-result parsing where the executor can expose both. A rejected command result may coexist with an observed child close. Conversely, PID absence or `exit` alone does not prove stdio close. Check an already resolved close before signaling and again when signal delivery reports false, but never turn a still-open pipe, rejected promise without close evidence, or unknown identity into success. Dispose stays idempotent and permanently closes the adapter to new work even on failure. No T2 or new recovery invocation before confirmed prior closure.

Acceptance: fulfilled close before disposal; close between initial check and failed signal; failed command with independently confirmed close; unresolved close with no live pid; real still-live child; concurrent dispose/timeout; SIGTERM and app End paths. State and `loop.log` must identify the same failure. Healthy close succeeds; unresolved closure retains failure and ownership protection.

## #168 — Profile sweep skip summary

Current path: `profile-cli.js:sweepStore` lists sessions and checks `terminalForMigration` before authority migration → catches all exceptions as string notices → game-loop bootstrap merges notices into new session state → UI displays every string. Bootstrap opens its session log only after sweep and engine initialization.

Make a normal nonterminal observation a structured skip, not a thrown failure: `{gameId, phase, code:'SESSION_NOT_TERMINAL'}`. Return these details alongside the existing `notices` strings, counters, and consumer failures. Display one informational summary with the skipped count and leave details in `loop.log` after `openLog()`. Persist only the bounded summary in UI notices. Unknown/malformed phase remains explicitly identified; actual unreadable state, migration, evaluation, and consumer errors retain failure wording and identifiable diagnostics.

Do not change authority, pending items, or lifecycle for skipped sessions. Do not add a persistent cross-boot suppression ledger: a still-nonterminal session remains an observable skip on each boot, once per sweep. Once independently recovered/ended and consumed, it naturally leaves this skip set; repeated terminal sweep must be idempotent. This resolves duplicate notices without falsely claiming all abandoned historical sessions were repaired.

Acceptance: three mixed nonterminal phases yield one summary and three gameId/phase log details; migration/consumer failure still visible; skipped files byte-identical; repeated boot does not accumulate duplicate per-session notices; recovered terminal session leaves skip summary and is consumed once.

## #181 — Preserve unresolved LLM decisions

Current path: `shared/game-setup.js` → session manager `.app-setup.json` → `session-launcher.js` → game-loop runtime/watchdog → `player-runtime.js:runOnce` → validated decision → version-guarded engine `step` → publish/metrics. Current watchdog uses T1/T2 and eventually `--force-default`. Ordinary managed pause is a boundary after the active decision; calling it alone cannot preserve the unresolved action.

### Budget and attempt contract

Introduce one validated, versioned player budget shared by managed/legacy entrypoints: `softWaitMs`, `hardTimeoutMs`, and bounded recovery-attempt count. Provisional product default: soft 25,000 ms, hard 300,000 ms; both are configurable before start, with `0 < soft < hard <= 3,600,000` and integer validation. Five minutes is a finite operational allowance, not a measured claim of inference sufficiency. Show that caveat in evidence, not as implementation jargon in the lobby. Existing `opts.watchdog` tests can use a compatibility adapter, but new production sessions must not silently restore 25/15 behavior. Resume restores persisted settings; omitted settings in historical sessions resolve to the explicitly documented new fail-preserving default and are stamped before invocation. Conflicting explicit resume settings require an intentional recovery budget update, not silent override.

Soft expiry only updates waiting state and elapsed time; it does not kill or replace the call. Hard expiry terminates and confirms closure. An explicit extension may increase a running call's deadline only through a bounded revisioned command that the actual runtime timer observes; if this is not implemented initially, permit budget extension for the next manual retry and label it accordingly. Do not advertise live extension unless tested end to end.

Default hard timeout has no automatic repeat. Known restored-session rejection may receive one repair + redecision under the original remaining hard budget, preserving the existing bounded repair contract. CLI/transport, malformed output, and illegal action get at most one classified retry only after closure and under an explicit remaining decision budget; conservative initial implementation may route these directly to manual recovery. Containment/close uncertainty is a safety failure with retry disabled. Retries never become policy/check/fold actions.

### Durable decision state

Before starting a player call persist a versioned record in loop state (or a dedicated private atomic file) containing game epoch, decisionId, playerId, expected engine stateVersion, attempt generation, status, budget, start time, and redacted attempt summaries. States: `running` → `accepted` or `recovery_required`; hard/parse/transport exhaustion enters recovery with no engine step. A process crash with `running` is a recovery requirement, not permission to replay automatically. Do not persist raw model thought or secrets; regenerate the actor view only after engine identity revalidation.

The engine is the authority at every recovery boundary. Read `step` and compare epoch/decisionId/actor/version before retry and before application. Increment attempt generation on recovery; late results from an old generation cannot apply. Engine `--expect-version` remains the final fence. If a crash occurred after step but before clearing the pending record, reconcile against the persisted engine decision/action: mark already applied only with exact evidence, otherwise report stale/unavailable. Never reapply merely because a record says pending.

Managed UX exposes waiting/soft-wait and recovery reason with Retry and End. Use durable command requestId and control revision checks; duplicate clicks have one result. Ordinary Resume must leave a recovery-required decision parked; only explicit Retry starts a new attempt. Recovery pause and normal user pause are distinguished in state while using the existing action gate. End aborts through the current terminal transaction and does not inject a poker action. Managed startup still parks restored sessions. Legacy `--resume` preserves recovery state; add an explicit `--retry-decision <decisionId>` contract (and documented end command) guarded by epoch/version, rather than implicit replay. SIGTERM stops children and leaves recoverable state.

### Observability and compatibility

Persist per-attempt runtime/model identifier (requested and reported when available), attempt number, budget, wall elapsed, cause category, closure result, and repair/retry outcome. `modelMs` is CLI round-trip wall time, not thinking-token time. Report successful completion latency separately from timed-out/censored attempts, with total attempts, resolved decisions, error counts, and sample exclusions. Historical `forced_default` stays historical and is not a timeout-specific metric. Policy path and existing review readers tolerate additive fields; malformed new recovery schema fails closed. No raw private prompts, output reasoning, or tokens enter diagnostics.

Acceptance: >25-second fixture completes once within configured hard deadline; soft wait leaves child running; hard failure changes no chip/bet/turn/history; all recovery state survives restart; old result, duplicate Retry, pause/resume, version change, and apply-before-crash cannot double act; exhausted repair budget stops; unresolved closure blocks retry; managed and legacy settings demonstrably reach the actual child timer.

## #174 — Position, mixed sizing, and public line strategy

The issue's baseline description predates current default strategy-v2. `policy-player.js:distributionFor` already dispatches `training/policies/strategy-v2.js`, whose strength estimate includes a position bonus and postflop public-card Monte Carlo. It still chooses one size per spot, and bluff weight is not gated by an explicit public line. Extend this versioned family; do not downgrade existing policy games to baseline-v1.

Producer path: `engine/decision.js:snapshotDecision` includes actor holes, public board/seats, positions from `engine/positions.js`, and sanitized `priorActions` → policy features/distribution → seeded sample and legal-output validation → engine decision reason/policy provenance → archived record/review and `benchmark-policies.js`. Only the actor's own holes and public information may enter features. Other players' hidden cards, future board, selected action, and result cannot influence the distribution.

Create a pure public-line classifier: active opponents, in-position status, last preflop aggressor, prior-street aggressor, checked-to state, current-street raises, and whether the actor previously surrendered initiative by check/call. Missing/contradictory public context yields no bluff eligibility. Classify own hand as value, draw/semi-bluff candidate, or weak showdown using deterministic public-card features; avoid treating equity versus a uniform random opponent as a solver range estimate.

Use explicit position/context frequency adjustments for unopened, facing-open, and facing-3bet spots. Retain persona distinctions. Postflop semi-bluff requires a real draw plus a supported aggression/position line; pure bluff requires a defined checked-to late-position/initiative line and no contradictory recent action. A continuation barrel requires actor aggression on the previous street or a separately named checked-through probe condition. Exclude unsupported multiway/safety-edge lines initially. Aggregate bluff mass must be capped by the context's value opportunity mass via a documented heuristic cap, with denominator and exclusion counts in the benchmark.

Select sizing from a shared support for value and eligible bluff actions within a spot: preflop open support e.g. 2.25/2.5/3 BB, postflop support e.g. 0.5/0.75 pot; actual legal unit, existing facing-raise formulas, min-raise, and stack cap remain canonical in `sizing.js`. These are heuristic settings to calibrate in benchmark, not optimal sizes. Merge equal clamped amounts and normalize once. Both value and eligible bluff classes must have nonzero mass on the same legal sizes; amount alone must not deterministically identify class in those supported spots. Preserve deterministic `deriveUnit(policySeed, gameEpoch, decisionId, policyId)` sampling and retry stability.

Bump strategy version/config digest and explicitly support safe roll-forward for stored known predecessors, including derived self-exploiter strategy versions. Raw past events retain their original version. Unknown or mismatched config remains an error. Mirror's observed distribution must not be silently overwritten; document whether it uses only shared sizing/legality or the new line model.

Acceptance: independent seeded sampling matches declared distributions within fixed tolerances; same marginal hand across UTG/CO/BTN differs in intended direction; value/bluff size support overlaps; line-ineligible spots have zero bluff mass; legality/chip conservation/all-in/min-reraise tests pass; hidden-card/future-result perturbations have identical distributions; benchmark reports coverage, position/persona frequencies, size mixture, bluff eligibility violations, seed, sample count, and wall cost.

## #175 — Favorable deal with sample provenance

Add `dealBias: off|light|strong` to browser-safe setup, legacy `--deal-bias`, app prefill/start/restart, engine configuration, session catalog display, and resume validation. Default is off. The setting is immutable within a session; resume omission restores stored value, mismatch is rejected. Historical missing setting means off only when no new deal-selection contract marker is present.

Use a versioned finite weighted selection over all 1,326 unordered user hole-card combinations. Define a simple inspectable playable-class predicate (pairs, suited aces, two broadways, suited connectors 65s or higher), fixed weights off=1 everywhere, light=2 for predicate/1 otherwise, strong=4/1. Enumerate combinations once; sample by cumulative weights using the supplied RNG. Randomize selected-card order and uniformly shuffle the remaining 50 cards; insert user cards into the two user positions in the existing deal order. Opponent and board draws are uniform conditional on the selected holes. Their marginal distribution necessarily changes when user holes are conditioned; make this explicit in help/docs. Off executes the original shuffle/deal path exactly, without extra RNG draws. No rejection loop, best-of-N board selection, or lookahead. Explicit test decks must either be rejected with non-off mode or supplied with an explicit test-only selection proof; they cannot accidentally masquerade as unbiased production deals.

Producer/persistence chain: validated engine config → `hand.js:startHand` canonical `{schemaVersion, algorithmVersion, mode}` deal-selection marker → active hand and archived `lastHand`/hand record → `decision.js` user snapshot projection → evaluator → training item/consumer event → profile, mistake bank, spaced repetition/mastery/goals, and tendency input. Record the marker for every hand under a non-off session, including naturally weak selections. Do not mark only the favored subset: every sample comes from the weighted distribution.

Use separate `dealSelection` provenance, not `hintShown`: `shared/assistance.js` currently validates an exact three-key hint object. Add a shared deal-selection parser and eligibility combiner, and canonical-origin verification beside `tools/assistance-proof.js` before training consumption. New session/hand contract markers make omitted or inconsistent selection data unavailable, not historical off. Event schema revisions must require the new marker; old compatible events retain historical interpretation. End-to-end verification must catch marker removal from a new-format event even if the envelope schema was also downgraded, by checking authoritative session/record provenance.

Exclude non-off decisions from independent score, mix distributions, leak/mistake creation, retest scheduling, mastery and goals. They may remain visible as practice activity and factual review with an explicit exclusion reason. `handAssistanceDisposition`/`training/tendency/extract.js` must exclude the entire biased hand, including zero-user-action blind all-ins, from the independent 60-hand self-model sample. Preserve hint assistance independently; off plus hint-on still excludes for hints. Profile coverage can count biased practice separately without increasing independent denominators. No retroactive rewrites of existing unbiased profile events.

Acceptance: off byte/seed/RNG-path equivalence; unique 52-card deal and conservation in 2–9 seats; exact expected weighted-combination probability and sampled light/strong movement; conditional remaining-card fairness; both entrypoints/restart/resume round trip; provenance stripping/corruption rejection; every independent consumer receives zero contribution from biased fixtures while factual activity remains; 59 independent + many biased hands remains insufficient for self modeling, 60 independent qualifies.
