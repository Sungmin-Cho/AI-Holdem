# AI 홀덤 — 설계 스펙

날짜: 2026-08-26
상태: 사용자 설계 승인 완료 (섹션별 승인), 스펙 리뷰 대기

## 1. 개요

AI와 함께 즐기는 노리밋 텍사스 홀덤. 메인 Claude 세션이 딜러가 되어 게임을 진행하고, AI 플레이어들은 각자 랜덤 페르소나를 부여받은 독립 에이전트로 스폰된다. 게임은 로컬 웹 UI에서 진행되며, 사용자는 브라우저에서 베팅 등 액션을 입력한다. 핸드마다 짧은 코칭 피드백이 쌓이고, 게임이 끝나면(사용자 버스트 = 패배, AI 전원 탈락 = 우승) 전체 핸드 히스토리 기반 종합 리뷰로 실력 향상을 돕는다.

목표: AI와 홀덤을 **즐기면서** 사용자의 실력이 **늘게** 하는 것.

## 2. 확정 결정사항

| 결정 | 내용 |
|---|---|
| 스택 | Node.js 단일 프로세스, 무빌드, 외부 의존성 0개. 서버→브라우저 SSE, 브라우저→서버 fetch POST |
| AI 플레이어 | 풀 에이전트 팀 — 플레이어마다 독립 에이전트 스폰, 게임 내내 유지 (접근안 A) |
| 규칙 판정 | 전부 순수 코드(엔진). LLM은 규칙·칩 계산을 하지 않음 |
| 테이블 | 2~9인 지원 (사용자 + AI 1~8명), 기본 4인 (AI 3명) |
| 블라인드 | 핸드 수 기반 레벨업 (기본 8핸드마다), 시작 스택 5,000 / 블라인드 25·50 |
| 코칭 | 핸드별 짧은 피드백 + 종료 시 종합 리뷰. 진행 중에는 비공개 정보 사용 금지 |
| AI 스타일 | 사용자에게 비공개. 종합 리뷰에서 공개 |
| 스킬 위치 | `.agents/skills/start-game/` 정본(SSOT), claude·grok은 심볼릭 링크로 연결 |
| UI 언어 | 한국어 |

## 3. 아키텍처

실행 중 참여자는 세 종류다.

```
┌─────────────┐  Bash(engine CLI)   ┌──────────────┐
│ 딜러         │────────────────────▶│ 포커 엔진      │── game/state.json (진실의 원천)
│ (메인 세션)   │                     │ (순수 JS CLI) │── game/hands/hand-NNNN.json
└──┬───────┬──┘                     └──────────────┘
   │       │ SendMessage(상황) / JSON 액션 응답
   │       ▼
   │    ┌────────────────────┐
   │    │ 플레이어 에이전트들     │  (Agent tool로 스폰, 게임 내내 유지)
   │    └────────────────────┘
   │ HTTP POST /api/publish (이벤트·화면 상태)
   ▼
┌─────────────┐   SSE /api/events   ┌──────────────┐
│ 웹 서버       │────────────────────▶│ 브라우저 UI    │
│ (server.js)  │◀────────────────────│ (포커 테이블)   │
└─────────────┘  POST /api/action   └──────────────┘
        ▲ GET /api/wait-action (long-poll)
        └── 딜러가 사용자 액션 대기
```

- **웹 서버**는 게임 로직이 전혀 없는 중계기다: 정적 UI 서빙, 딜러가 게시한 이벤트의 SSE 중계, 사용자 액션 큐잉, 마지막 화면 상태 캐시(`/api/snapshot`, 새로고침 복구용).
- **딜러(메인 세션)**는 오케스트레이터다: 엔진 CLI 호출로 상태 전이, AI 차례면 에이전트에 SendMessage, 사용자 차례면 long-poll 대기, 모든 이벤트를 서버에 게시, 딜러 멘트로 나레이션, 핸드 종료 시 코칭 코멘트 생성.
- **진실의 단일 원천은 `game/state.json`** (엔진만 읽고 쓴다). 딜러 세션 컨텍스트가 요약되거나 서버가 재시작돼도 게임은 상태 파일에서 복원된다.

### 게임 루프 (딜러 절차)

```
1. 사전 점검 (node 존재, 포트, 기존 게임 유무)
2. engine init (페르소나 랜덤 생성 포함) → 서버 백그라운드 기동 → 브라우저 열기
3. 플레이어 에이전트 스폰 (명명 에이전트, 페르소나 카드 전달)
4. 반복 (게임 종료까지):
   a. engine new-hand  → 블라인드 게시·딜링 이벤트 게시
   b. 핸드 진행 중 반복:
      - engine legal → 다음 행동자 + 가능 액션
      - 사용자 차례: /api/wait-action long-poll (타임아웃 시 재시도, 무한 대기 허용)
      - AI 차례: 해당 에이전트에 상황 전송 → JSON 액션 수신
      - engine apply → 결과 이벤트(스트리트 진행·팟 정산 포함) 게시
   c. 핸드 종료: 히스토리 아카이브, 코칭 코멘트 생성(비공개 정보 제외) 게시,
      버스트 처리(AI면 작별 멘트 후 퇴장, 사용자면 게임 종료), 레벨업 안내
5. 게임 종료: 전체 히스토리 기반 종합 리뷰 생성 → UI 리뷰 화면 게시 → 에이전트 정리
```

## 4. 포커 엔진 (`engine/`)

순수 JS, 의존성 0, 상태 파일 기반 CLI. 모든 명령은 JSON을 stdout으로 출력한다.

### 규칙 범위

- 노리밋 텍사스 홀덤, 2~9인, 버튼/SB/BB 로테이션 (헤즈업 특례: 버튼=SB 포함)
- 미니멈 레이즈 규칙 — 언더 레이즈 올인은 베팅을 다시 열지 않는 규칙 포함
- 올인·사이드팟(다중), 스플릿 팟(홀수 칩은 버튼 왼쪽 첫 좌석부터)
- 쇼다운 공개 규칙: 마지막 공격자부터 공개, 진 패는 머킹(비공개) 처리
- 올인 후 콜 완료 시 잔여 보드 자동 런아웃
- 7카드 핸드 평가기 자체 구현 (하이 핸드만, 로우 없음)
- 셔플: `crypto.randomInt` 기반 Fisher-Yates
- 블라인드 스케줄: 25/50 → 50/100 → 75/150 → 100/200 → 150/300 → 200/400 → 300/600 → 400/800 → 500/1000 → 700/1400 → 1000/2000 → 이후 매 레벨 ×1.5 반올림. 앤티 없음
- 통계 집계: 플레이어별 VPIP, PFR, 공격 빈도, 쇼다운 승률, 핸드별 수지

### CLI 명령

| 명령 | 역할 |
|---|---|
| `init --ai <n> [--stack N] [--blinds SB/BB] [--level-every N]` | 게임 생성. 페르소나 랜덤 생성 포함 → `game/state.json`, `game/players.json`. 사용자 좌석의 playerId는 `user`(UI 표기 "나") |
| `new-hand` | 셔플·딜링·블라인드 포스팅·레벨업 판정. 결과 이벤트 배열 반환 |
| `legal` | 현재 행동자 + 합법 액션 목록(콜 금액, 레이즈 범위) |
| `apply <playerId> <action> [amount]` | 액션 검증·적용. 베팅 라운드 종료 시 다음 스트리트, 쇼다운, 팟 분배까지 자동 진행하고 발생 이벤트 전부 반환 |
| `apply <playerId> --force-default` | 무응답 플레이어 강제 처리 (체크 가능하면 체크, 아니면 폴드) |
| `view --for <playerId\|user>` | 해당 관점으로 편집(redact)된 화면 상태. UI 게시는 `--for user` |
| `hand <n> [--redacted]` | 핸드 히스토리 조회. `--redacted`는 사용자 관점에서 공개된 정보만 (핸드별 코칭용) |
| `stats` | 누적 통계 (종합 리뷰용) |
| `end --result <lose\|win\|abort>` | 게임 종료 마킹 |

- 불법 액션은 명확한 오류 JSON으로 거부한다. 딜러는 state.json을 직접 수정하지 않는다.
- `game/state.json`에는 덱(미공개 카드)이 포함된다 — 엔진과 딜러만 접근하고, UI에는 `view` 결과만 게시되므로 노출되지 않는다.
- 핸드 종료 시 엔진이 `game/hands/hand-NNNN.json`(전체 정보 포함)을 기록한다.

## 5. 웹 서버 (`server/server.js`)

Node 내장 `http`만 사용. 포트 기본 8877 (`--port` 옵션).

| 엔드포인트 | 역할 |
|---|---|
| `GET /` 및 정적 파일 | 포커 테이블 UI (`server/public/`) |
| `GET /api/events` | 브라우저 SSE 구독 (이벤트 스트림) |
| `GET /api/snapshot` | 마지막 게시 상태 (새로고침·재접속 복구) |
| `POST /api/publish` | 딜러가 이벤트 배치 + 화면 상태 게시 → SSE 브로드캐스트 + 스냅샷 갱신 |
| `POST /api/action` | 사용자 액션 `{action, amount?}` 큐 적재 |
| `GET /api/wait-action?timeoutMs=25000` | 딜러 long-poll. 액션 도착 시 즉시 반환, 타임아웃 시 `{timeout:true}` |

서버는 액션의 합법성을 판단하지 않는다(딜러가 엔진으로 검증). UI가 내 차례에만 버튼을 활성화해 1차로 거르고, 차례가 아닐 때 도착한 액션은 딜러가 버리고 안내 이벤트를 게시한다.

## 6. 플레이어 에이전트

### 페르소나 (스폰 시 랜덤 생성, `game/players.json`에 저장)

- 이름·말투·성격 (한국어 이름 풀에서 추첨, 겹치지 않게)
- 아키타입 6종 중 추첨: TAG(타이트 공격형) / LAG(루즈 공격형) / Nit(극단 수비형) / Calling Station(콜쟁이) / Maniac(광인) / Trickster(트랩형)
- 세부 파라미터 변주: 블러프 빈도, 3벳 성향, 틸트 성향 등 (같은 아키타입도 매번 다르게)
- **스타일은 사용자에게 비공개.** UI에는 이름·아바타만. 종합 리뷰에서 공개된다.

### 통신 프로토콜

딜러 → 에이전트 (매 차례, 자족적 요약):

```
[핸드 12 / 턴] 당신: 서연 (BTN, 스택 4,300)
홀카드: A♠ K♦ | 보드: K♥ 7♣ 2♦ 9♠
팟: 850 | 블라인드 50/100
이번 핸드: 민수(UTG) 폴드, 지혜(BB) 체크, … 지혜가 300 벳
가능한 액션: fold / call 300 / raise 600~4300
JSON 한 줄로 응답: {"action":"...","amount":숫자?,"talk":"짧은 한마디(선택)"}
```

에이전트 → 딜러: JSON 한 줄 `{action, amount?, talk?}`. `talk`는 이벤트 로그에 테이블 톡으로 표시.

- 스폰 프롬프트: 페르소나 카드 + 행동 규약 (항상 JSON으로만 응답, 캐릭터 유지, talk는 1문장 이하, 자기 스타일을 직접 발설하지 않기, 매 요약은 자족적이므로 계산은 요약 기준으로).
- 응답 파싱 실패 또는 불법 액션 → 1회 재요청 → 그래도 실패하면 `--force-default` (게임은 절대 멈추지 않는다).
- 버스트 시: 작별 멘트 한 줄 요청 후 퇴장 처리 (에이전트 종료).

## 7. 웹 UI (`server/public/`)

vanilla HTML/CSS/JS 단일 페이지. 그린 펠트 포커 테이블.

- 타원 테이블 둘레 좌석: 아바타·이름·스택·현재 베팅 칩·상태(폴드/올인/차례 하이라이트), 딜러 버튼 표시
- 중앙: 커뮤니티 카드, 팟(사이드팟 구분 표시)
- 내 홀카드만 앞면, 상대는 뒷면. 쇼다운 시 규칙에 따라 공개
- 하단 액션 바 (내 차례에만 활성화): 폴드 / 체크 / 콜(금액 표시) / 레이즈 슬라이더 + 프리셋(최소·½팟·팟·올인). 시간제한 없음
- 우측 패널 탭 2개: **이벤트 로그**(딜러 나레이션·액션·테이블 톡) / **코치**(핸드별 피드백 누적)
- 상단 바: 현재 블라인드 레벨, 다음 레벨업까지 남은 핸드 수, 핸드 번호
- 게임 종료 시 종합 리뷰 오버레이 화면
- SSE 끊김 시 자동 재접속 + `/api/snapshot`으로 상태 복구
- 전부 한국어

## 8. 코칭

### 핸드별 피드백 (코치 패널)

핸드 종료마다 딜러가 `hand <n> --redacted`(사용자 관점에서 공개된 정보만)를 보고 사용자의 주요 결정 1~2개에 1~2줄 코멘트. 팟 오즈·포지션·레인지 개념을 실제 수치와 함께 사용. **공정성 규칙: 핸드 중 공개되지 않은 상대 홀카드는 절대 사용하지 않는다** (엔진의 redacted 뷰가 이를 강제). 사용자가 프리플랍에서 접은 핸드는 코멘트를 생략한다(프리플랍 폴드 자체가 주목할 결정인 경우만 예외).

### 종합 리뷰 (게임 종료 시)

전체 핸드 아카이브(비공개 정보 포함)와 `stats` 기반:

1. 내 성향 통계: VPIP, PFR, 공격성, 쇼다운 승률 + 해석
2. 결정적 핸드 2~3개 리플레이 분석 (이때는 접힌 패 포함 전체 공개)
3. 각 AI의 실제 아키타입 공개 + 내가 잘/못 읽은 부분
4. 다음 게임에서 연습할 것 1~2가지

UI 리뷰 오버레이로 표시하고, `game/review.md`로도 저장.

## 9. 크로스 에이전트 스킬 (`.agents/`)

사용자는 Claude Code · Grok Build · Codex 세 호스트를 사용한다. 스킬 정본은 호스트 중립 위치에 둔다.

```
.agents/skills/start-game/SKILL.md   ← 정본 (SSOT)
.claude/skills/start-game            ← 정본 디렉토리로의 심볼릭 링크
<grok 스킬 경로>/start-game           ← 심볼릭 링크 (경로는 구현 시 확인)
```

- SKILL.md 본문은 호스트 중립으로 작성: 게임 루프·엔진 CLI·서버 API는 공통이고, "플레이어 에이전트 스폰" 단계만 **호스트 어댑테이션 절**로 분리한다 — Claude Code는 Agent tool + SendMessage(지속 에이전트), 지속 에이전트가 없는 호스트는 결정 시점마다 페르소나 카드 + 딜러가 제공하는 상황 요약으로 1회성 에이전트를 띄우는 폴백을 명시.
- 구현 시 검증 항목: ① Claude Code가 심볼릭 링크된 프로젝트 스킬을 인식하는지 (안 되면 `.claude/skills/start-game/SKILL.md`를 정본을 참조하는 얇은 래퍼로), ② Codex가 `.agents/skills`를 네이티브 인식하는지 (안 되면 AGENTS.md 참조 또는 심볼릭 링크 브리지), ③ grok의 프로젝트 스킬 경로.

스킬 사용법: `/start-game [AI수 1~8]` (옵션 `--stack N`, `--level-every N`), `/start-game resume`(중단 게임 재개 — 상태 파일에서 복원, 에이전트 재스폰 후 상황 브리핑).

## 10. 신뢰성·복구

- 에이전트 무응답/깨진 응답: 1회 재시도 → `--force-default`. 게임은 멈추지 않는다.
- 서버 다운: 재기동하면 딜러가 마지막 `view`를 다시 게시. 브라우저는 자동 재접속.
- 딜러 세션 컨텍스트 요약: 상태는 전부 파일에 있으므로 `legal` 호출부터 그대로 재개.
- 중단된 게임: `/start-game resume`. 에이전트 기억은 리셋되지만(재스폰) 페르소나는 `players.json`에서 복원되고 게임 상태는 이어진다.
- 사용자 자리 비움: long-poll 타임아웃을 무한 반복하며 대기 (게임에 시간제한 없음).

## 11. 테스트 전략

- **엔진 단위 테스트에 집중** (`node --test`, 의존성 0 유지):
  - 핸드 평가기: 족보 전 등급 판별, 킥커 비교, 휠 스트레이트(A-2-3-4-5), 스틸 휠 플러시, 동점 스플릿
  - 사이드팟: 3인 이상 올인 시나리오, 홀수 칩 분배
  - 버튼/블라인드 로테이션: 3인 이상 + 헤즈업 특례, 탈락자 발생 시 버튼 이동
  - 베팅 규칙: 미니멈 레이즈, 언더 레이즈 올인의 재오픈 금지, 체크-레이즈
  - 상태 전이: 스트리트 자동 진행, 올인 런아웃, 강제 기본 액션
- 서버: 스모크 테스트 (publish → SSE 수신, action → wait-action 왕복)
- UI·전체 흐름: 수동 확인 + 브라우저 자동화 도구로 스모크
