# 리플레이 동시 읽기 오류 분류 확정

2026-10-16 구현 검토에서 확정한 설계 §5.1 보충 계약이다. 초기 설계·계획 문서는 검토 당시 바이트와 해시를 보존한다.

동시 엔진 원자 저장 중 일반 파일의 링크 수 0을 연속으로 관측해도 재시도 가능한 `REPLAY_BUSY`로 분류한다. 원래 조상 경로의 identity가 유지되고 현재 leaf가 안전한 단일 링크 일반 파일이거나 다시 링크 수 0인 일반 파일이어야 한다. 이 관측에서 파일을 새로 열거나 받은 바이트를 반환하지 않는다.

contained opener가 `UNSAFE_PATH`로 읽기를 거부했어도 바깥의 inode·크기·타임스탬프가 같을 수 있다. 현재 경로가 안전한 단일 링크 일반 파일이고 원래 조상이 같으면 바이트 반환 없이 `REPLAY_BUSY`다. 현재 크기가 파일 상한을 넘으면 기존 `REPLAY_LIMIT_EXCEEDED`를 유지한다. 동일 바깥 metadata의 영속 권한 오류는 `REPLAY_UNAVAILABLE`이다.

사라진 경로, 심볼릭 링크·다중 링크·특수 파일, 조상 교체는 `REPLAY_UNAVAILABLE`로 거부한다. 이 보충은 읽기 허용 조건, DTO 공개 범위, 저장 형식과 원본 무변경 계약을 바꾸지 않는다.

파일시스템이 링크 수를 영구히 0으로 보고한다면 기존 단일 링크 검사를 통과할 수 없으며 계속 재시도 안내가 표시될 수 있다. 이 경우 반복 새로고침으로 해결된다고 보장하지 않으며, 단일 링크 identity를 정상 제공하는 로컬 파일시스템이 필요하다. 이런 비정상 identity 보고를 실제 특정 파일시스템에서 관측했다는 주장은 아니다.

검증은 연속 링크 수 0의 state·hand 및 읽기 전·후/목록·상세, 바깥 metadata가 같은 opener 거부와 권한 오류 대조, 조상 교체, 실제 엔진 writer 겹침을 포함한다. 실제 파일시스템에서 inode 재사용이 일어난 빈도나 개별 CI 실패의 커널 수준 원인을 이 주입 테스트만으로 확정하지 않는다.
