# 학습 효과 평가 (프로토콜 v1)

학습실의 점수는 **휴리스틱 기준표 v3와의 일치도**입니다. 이 문서는 그 점수가 무엇을 재고 무엇을 재지 못하는지, 그리고 한 사람의 학습 변화를 미리 정한 규칙으로 관측하는 절차(`tools/learning-eval.js`)를 설명합니다. 결과는 개인 연관 관측입니다. 코칭의 인과 효과, 독립 전략 기준(solver/GTO)의 습득, 실제 테이블 실력·수익의 증거가 아닙니다.

## 현재 지표가 재는 것

| 지표 | 재는 것 | 재지 못하는 것 |
|---|---|---|
| 일치율(`allowedActionRate`) | 고른 행동이 기준표에서 빈도 > 0인 비율 | 정확한 전략. 허용 행동이 여럿인 칸은 관대합니다. |
| fold 기준선 | 같은 문항에서 항상 fold했을 때의 비율 | — (비교 기준값) |
| 새 문제 평가 | 그때 아직 답하지 않은 (spot, 손패)의 일치율 | 문항 구성이 매번 달라 단순 비교하면 쉬운 쪽으로의 이동이 개선처럼 보입니다. 같은 차트를 쓰는 다른 spot의 같은 손패는 "새 문제"로 들어올 수 있습니다. |
| 지연 재평가 | 같은 문항을 24시간 뒤 다시 푼 일치율 | 새 문항으로의 전이. 기준 평가 직후 정답을 봤고, 그 사이 같은 문항을 다시 연습해도 막지 않습니다. |
| 게임 기록 일치율 | 게임에서 만난 지원 spot의 일치율 | 만나는 spot이 통제되지 않습니다. |
| 일반화 연습 | 틀린 손패 이웃 연습 | 측정 실행이 아닙니다. |
| 칩 손익·승률 | — | 학습 효과 지표가 아닙니다(분산, 상대 정책·LLM 미보정). |

기준표 v1–v3는 원저작 휴리스틱입니다([학습 데이터 문서](../../training/data/README.md)). 이 리포에는 출처·라이선스·coverage가 확인된 독립 기준 자료나 전문가 검토 자료가 없습니다. 그래서 프로토콜 v1은 휴리스틱 일치도의 변화만 잽니다.

## 절차

```bash
node tools/learning-eval.js enroll --store /absolute/store --consent [--baseline-runs 3] [--intervention-days 7] [--post-days 7]
node tools/learning-eval.js status --store /absolute/store
node tools/learning-eval.js report --store /absolute/store --json > report.json
node tools/learning-eval.js withdraw --store /absolute/store
```

`npm run learning-eval -- <명령> ...`도 같습니다.

1. **등록(동의)**: 참여자가 `--consent`로 등록합니다. 기록은 로컬 store에만 남고, 언제든 `withdraw`로 철회할 수 있습니다.
   - 등록할 때 일정이 봉인됩니다: 기준 assessment K회(기본 3), 개입 D일(기본 7), 사후 W일(기본 7).
   - 사후 구간은 참여자가 고르지 않습니다. 봉인된 시각(`postOpensAt`)에 열리고 `postClosesAt`에 닫힙니다.
2. **기준**: 사후 구간이 열리기 전에 새 문제 평가 K회를 시작하고 끝냅니다. 시작 순서로 처음 K회가 기준이고, 시작했다가 끝내지 않은 실행도 슬롯을 차지합니다. 그래서 잘 안 된 실행만 골라 버릴 수 없습니다.
3. **개입**: 평소처럼 게임·코칭·연습·차트를 씁니다.
4. **사후**: 사후 구간에서 새 문제 평가 K회와, 기준 평가마다 지연 재평가 1회를 합니다.
5. **보고**: `postClosesAt` 뒤에 최종 보고서가 나옵니다. 그 전에는 진행 상황(`INTERIM`)만 나옵니다.

## 판정 규칙(사전 고정, 코드 상수 `LEARNING_EFFECT_PROTOCOL_V1`와 SHA-256으로 봉인)

- **문항 동치군**은 (기준표, 차트 id, 손패)입니다. 같은 차트의 같은 손패는 답이 같으므로 같은 문항으로 봅니다.
- **M1 — 미응답·미열람 동치군 문항 일치도(전이 근사)**: 기준 K회와 사후 K회의 깨끗한 문항을 비교합니다.
  - 깨끗한 문항은 그 문항에 답하기 직전까지 같은 동치군을 답한 기록(측정·연습·관측이 있는 게임)도, 같은 차트를 연 기록도 없는 문항입니다.
  - 노출 원장이 추적 시작(등록 7일 전)부터 기록을 보장하지 못하면 그 문항은 "확인 불가"로 제외합니다. 확인 불가를 미노출로 취급하지 않습니다.
  - 비교는 답 구조 셀(fold 허용 여부, 허용 행동 수, 합법 행동 수)로 직접 표준화합니다. 그래서 "항상 fold"나 "합법 행동 무작위"처럼 바뀌지 않은 정책은 문항 구성이 바뀌어도 차이가 0입니다.
- **M2 — 재연습 없는 지연 유지**: 기준 응답과 사후 구간 첫 재평가 응답의 짝입니다. 그 사이 같은 동치군 노출이 없고 24시간 이상 지난 짝만 씁니다. 재연습한 짝은 따로 기술값으로 싣습니다.
- **크기와 불확실성**:
  - 크기와 방향은 원자료 표준화 차이로 봅니다.
  - 불확실성은 M1이 셀별 Agresti–Caffo, M2가 Agresti–Min Wald+2 95% 구간입니다.
  - 최소 의미 변화(MDE)는 15%p입니다.
- **판정**:
  - IMPROVED: 구간 하한 > 0이고 차이 ≥ 15%p
  - DECLINED: 구간 상한 < 0이고 차이 ≤ −15%p
  - NO_MEANINGFUL_CHANGE: 구간이 ±15%p 안
  - INCONCLUSIVE: 그 밖
  - 작은 표본에서는 대부분 INCONCLUSIVE입니다. 이것이 정직한 결론입니다.
- **완료 게이트**:
  - M1은 기준·사후 2K 슬롯이 모두 완료돼야 판정합니다. M2는 K개 재평가가 모두 완료돼야 판정합니다.
  - 표본 하한은 M1 20문항, M2 10짝입니다. 계산 허용 하한이지 검정력 보장은 아닙니다.
  - 기준표 셀 가운데 사후에 없는 셀의 비중이 20%를 넘으면 비교 불가(NON_COMPARABLE)입니다.
- **패턴**: M2가 IMPROVED인데 M1이 판정 가능하고 IMPROVED가 아니면 `retention-without-transfer`(같은 문항 기억 가능성)입니다.

## 보고서 읽는 법

- `status`가 `FINAL`·`INTERIM`·`WITHDRAWN`·`NOT_ENROLLED`·`NON_COMPARABLE`이고, `reasons`에 사유가 있습니다.
- `runs`는 구간별 슬롯 분모입니다.
  - 계획
  - 시작
  - 미시작
  - 상태별
  - 확인 안 된 시작
  - 빈 큐
  - 다른 기준표
  - 교체
  - 관측 없는 게임 결정
- `items`는 문항별 포함·제외 사유입니다. 이탈·미적격·오염은 0점이나 개선으로 접지 않고 사유별로 셉니다.
- `m1`·`m2`에는 원자료 차이(`raw`), 보정 구간(`ci`), 셀별 표와 판정이 있습니다. `descriptive`에는 난이도 층·맥락·좌석·스택 분포와 개입 기간 활동이 있습니다.
- 보고서는 **지금 보존된 자료로 다시 계산한 값**입니다. 원장 상한·손상 뒤에는 달라질 수 있습니다. 최종 결과를 남기려면 `report --json` 출력을 저장하세요. `inputs`에 입력 파일 digest가 있습니다.
- `status`·`report`는 학습 기록을 바꾸지 않습니다(락·쓰기 없음). 학습 중에 읽어 기록이 계속 바뀌면 `SNAPSHOT_UNSTABLE`로 끝납니다. 학습을 멈춘 뒤 다시 실행하세요.

## 계측

- **노출 원장** `.training/grid-exposure-log.json`
  - 차트를 열 때마다 한 행을 덧붙입니다.
  - 처음 만들 때 기존 최근 열람 파일로 씨앗을 넣어, 만든 시각 7일 전부터의 열람 여부를 정확히 답합니다.
- **실행 원장** `.training/study-run-log.json`
  - 새 문제 평가·지연 재평가를 시작할 때 시작 의도를 남깁니다.
  - 미완료 측정 실행이 다른 시작으로 교체되면 교체 행을 남깁니다.
  - 응답 0건 실행·빈 큐·교체가 분모에서 사라지지 않게 하려는 것입니다.
- 두 원장은 상한(4,000행·2MiB)을 넘으면 오래된 행부터 버리고 보장 구간을 앞으로 옮깁니다. 손상 원본은 다른 이름으로 보존합니다.
- 기존 학습 기록·문항 생성·학습실 화면은 바뀌지 않습니다.

## 한계

- 결과는 한 사람의 전후 연관 관측입니다. 코칭 효과를 분리하는 개인 내 교차 설계(spot 묶음별 코칭 끄기)는 제품 토글·동의·carryover 처리가 필요해 하지 않았습니다.
- 다음 노출은 문항 단위로 알 수 없습니다.
  - 추적 시작(등록 7일 전) 이전의 노출
  - 관측이 없는 게임 결정(coverage 투영·판단 보조 사용)
  - 코치 노트 속 다른 손패 언급
- 판단 보조는 공개 산술만 보여 주므로 정답 노출로 보지 않습니다.
- 구간은 문항 독립을 가정한 근사입니다. 같은 실행·같은 차트 안의 상관은 다루지 않습니다.

## 코칭 품질 점검(효과와 별개)

효과 측정과 별도로, 코치 노트의 품질을 다음 rubric으로 점검합니다.
- **표본**: 등록 기간의 코치 노트에서 등록 id를 시드로 균등 추출합니다. 20개, 적으면 전부입니다.
- **검토자**: 결과(사후 점수·손익)를 보지 않습니다. 사람 또는 코치와 다른 모델 가족입니다.
- **항목**(0/1 + 근거 메모):
  1. 사실·산술 오류 없음
  2. 근거 없는 EV·GTO·solver 주장 없음
  3. 결정 시점 이후 정보 언급 없음
  4. 다음 연습 제안이 그 spot과 맞고 실행 가능함
- rubric 버전·검토자·시드·제외 수를 함께 기록합니다.
